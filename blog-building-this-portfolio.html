Building This Portfolio
A Case Study

Every pixel, every animation, every line of CSS — this portfolio wasn't designed. It was engineered. Here's the story behind its creation.

The Vision

I didn't want a template. I wanted a system. A digital presence that reflects how I think about code: structured, intentional, and obsessed with craft. The brief was simple — build a multi-page portfolio that feels like a product, not a resume.

Design System First

Before writing a single line of HTML, I defined the design tokens: dark primary (#060608), amber gold accent (#d4a843), and a typography stack built around Syne (display), Outfit (body), and DM Mono (code). Every color, spacing unit, and font weight was locked in as CSS custom properties before any component existed.

The dark theme isn't just an afterthought — it's the primary theme. The light theme was derived from it, ensuring both modes feel equally polished. This approach, dark-first, guarantees the portfolio looks its best in the environment where most developers and recruiters will view it.

Architecture Decisions

This site is pure HTML, CSS, and JavaScript — no frameworks, no build tools. Every page is a static .html file, making it instantly deployable, lightning fast, and fully crawlable by search engines. The trade-off? More manual work maintaining shared components like the navbar and footer across 7+ pages.

The navigation uses a hash-scroll pattern for cross-page anchoring (index.html#about), giving the illusion of a single-page app while keeping the benefits of static HTML. The mobile nav slides in from the right with a blur backdrop — a pattern common in SaaS products, recreated here without a single dependency.

Visual Identity

The amber gold accent isn't decorative — it's structural. It draws the eye to interactive elements, section labels, and the JSON card on the About page. The custom cursor with mix-blend-mode: difference creates a premium, exploratory feel. The noise overlay adds texture to what would otherwise be flat dark surfaces.

Perhaps the most intentional detail: the hero animation. Instead of relying on JavaScript scroll triggers, I used CSS keyframes (heroReveal) with staggered delays for each title line. The result is a page that loads ready — no layout shifts, no flickering — immediately communicating quality.

The Project Cards

The Dzire and MultiThreaded Text Analyzer cards aren't just links — they're entry points into rich modals with role-based screenshot tabs and video demos. The modal system was refactored into a reusable setupModal() function that handles open, close, and overlay click for any project. The Dzire modal includes role tabs (Visitor, Student, Teacher, Admin) that swap screenshots dynamically, giving a product tour experience without leaving the page.

Performance & SEO

Every page includes Open Graph tags, Twitter cards, canonical URLs, and JSON-LD structured data. Images use loading="lazy" with object-fit: cover for consistent cropping. The CSS is a single 2000+ line file — intentionally unminified during development for readability, ready for production minification.

Lessons Learned

  • Design in the browser — mockups lie. The real design happens in CSS.
  • Dark-first theming is easier than retrofitting dark mode onto a light design.
  • CSS custom properties make theme switching trivial — one attribute change on <html> swaps the entire palette.
  • Static doesn't mean simple — a multi-page static site requires more discipline than a framework, but the performance payoff is real.

Built with precision, passion, and way too many hours in the browser inspector.
